How a paper gets into the workbook

A paper comes from one of two sources. Seed references come from two PDFs. New papers come from database searches. Each source has a check against the database answer before the data reaches the workbook.

  • The seed scripts look up each reference in Crossref, OpenAlex, NTRS and arXiv, and cache every answer.
  • verify_candidates.py compares each search result with the stored raw answer, to catch invented references.
  • merge_candidates.py removes duplicates and gives the ids N001 to N161.
  • import-json writes rows. check then tests the rules.
  • zotero_push.py is a dry run unless you add --apply.

How import-json finds the row to update

import-json is an upsert: it updates a matching row or adds a new one. It tries three keys in a fixed order. It only writes fields that are not empty, and it never deletes a row. This lets an agent run the same import twice without duplicates.

What the check enforces

lit_tool.py check prints each problem as SHEET!ROW: message and exits 1 if any exist. The main rules protect against uncited or invented papers.

  • A verified paper needs an id type (DOI, arXiv, NTRS, ISBN or URL), an identifier and evidence.
  • read_level must be 0 to 3. Stage tokens must be S1 to S4.
  • Citekeys, seed ids and DOIs must be unique.
  • A card takeaway needs a page number. Every citekey on another sheet must exist in Papers.

# literature/ - literature-review toolkit

Design: `backlog/docs/doc-14`. Four stages: S1 Value, S2 Method, S3 Improvement,
S4 Robustness. The join key between Zotero and the spreadsheet is the
Better BibTeX citekey.

## Folder layout
- `lit_toolkit.xlsx` - the spreadsheet: About, Papers, Map, Architecture
  comparison, Reading queue, Cards, Lookup index, Feedback log, Search log,
  Vocabularies. Start with the About sheet (every column explained).
- `library.bib` - Better BibTeX auto-export of the Zotero library. Do not edit.
- `seeds/` - harvested seed data (references from the two seed PDFs).
- `tools/` - `lit_tool.py` (the tool) and `test_lit_tool.py` (its tests).
- PDFs are never committed (`literature/**/*.pdf` is git-ignored). Zotero keeps
  the PDFs in `~/Zotero/storage`.

## Rules (short)
- Every paper has a DOI, arXiv id, NTRS id, ISBN, or stable URL, unless
  `verify_status` says `web-only` or `not-found`. Never cite from memory.
- Every takeaway on a card has a page number.
- Agents add and update rows. They never delete rows.
- The user approves reading-queue and pull-list choices.

## Commands (run from the repo root)
Check the workbook. It prints each problem as `SHEET!ROW: message` and exits 1
if there are any; otherwise it prints one OK line:

    python3 literature/tools/lit_tool.py check [--xlsx PATH]

Add or update Papers rows from a JSON list (field names = Papers columns).
It matches on seed_id, then citekey, then DOI. It only fills fields that are
non-empty in the JSON and never deletes rows:

    python3 literature/tools/lit_tool.py import-json PATH [--xlsx PATH]

Dump the Papers sheet to JSON:

    python3 literature/tools/lit_tool.py export-json PATH [--xlsx PATH]

`init` creates an empty workbook and refuses to overwrite an existing one
unless you add `--force`:

    python3 literature/tools/lit_tool.py init [--force]

Tests: `python3 -m unittest literature/tools/test_lit_tool.py -v`
